# DESERT Doppler extension — plan (Phase 5)

Planning document, 9 Oct 2026. No DESERT code has been changed. Sources read: DESERT 4.0.0
(`DESERT_Underwater/DESERT_Framework/DESERT`), ns-miracle 2.0.0 and WOSS 2.0.1 (`.unpacked_folder`).

## 1. Goal

Give DESERT what our waveform simulator shows: **Doppler is generated by the nodes' motion, and how much of it is
left depends on who compensates it.** At network level the extension must let a user
- drive nodes with real or synthetic wave motion (velocity, not only position);
- choose, per node, a compensation placement (receiver only, own IMU at either end, split, IMU + per-symbol receiver)
  with sensor quality (IMU drift, latency, lever arm, path-direction error) and a receiver estimate budget;
- see the residual Doppler as interference in the PHY's SINR, hence in PER, throughput, retransmissions, energy.

Out of scope for the first version: waveform-level simulation inside DESERT (DESERT is packet-level), new estimators
(ground rule), multi-user interference between Doppler-shifted users (C3, Phase 4; a hook is planned).

## 3. Architecture

Five pieces. The model code is kept free of ns-2 so that it can be unit-tested against the Python implementation.

```
            Tcl: per-node sensors, placement, receiver budget, motion file
                                   |
 [B] UwWavePosition  ---velocity(t)--->  [C] UwDopplerOfdmPhy (extends UwOFDMPhy)
     (Position + UwVelocityProvider)          endTx: tag packet (hdr_uwdoppler)
 [D] UwDopplerRegistry (node id -> Position*) endRx: eps(t) on the packet -> residual -> I_D
                                   |                -> SINR' -> getOFDMPER
                                   v
            [A] libuwdoppler (plain C++): motion, IMU model, stages, interference, floor
            [E] Python side: trace exporter, reference fixtures, cross-check scripts
```

### [A] `uwdoppler` model library (plain C++17, no ns-2 headers)
Mirror of `placement.py` / `theory.py`, per packet and in the time domain:
- `MotionTrace`: samples of position, velocity, acceleration, lever-arm velocity (gyro × arm) at `fs`; interpolation
  at arbitrary times (cubic or windowed sinc; must not introduce kinks — Phase 1 lesson).
- `ImuModel`: Gauss–Markov drift (sigma, tau) as a running process per node (seeded); latency with optional
  extrapolation by the measured acceleration; lever arm corrected or not; direction error (azimuth offset of u).
- `NodeStage`: the node's estimate of its own share on a time grid: `x(t - L) + L x'(t - L) + drift`.
- `ReceiverStage`: none / per symbol / constant or line from first and last symbol / quadratic from all symbols /
  fed-back value; estimates at symbol centres with error sigma_rx; returns the compensation trajectory.
- `interference(residual, grid, windows, fc)`: mean over FFT windows of the variance of
  `Theta(t) = 2 pi fc int r dt` (the `theory.kernel_ici` quantity, computed directly on the packet's residual);
  plus `pathFloor(powers, surface flags, grazing angles, var(w))`.
- Cost: a packet of `N` symbols on 16–32 points per symbol: a few thousand samples — negligible per packet.

### [B] Wave mobility: `UwWavePosition` (+ velocity interface)
- `class UwVelocityProvider` (pure interface): `velocity(t)`, `acceleration(t)`, `leverVelocity(t)`.
- `UwWavePosition : public Position, public UwVelocityProvider`: mean position + slow drift (constant velocity or
  waypoints) + fast motion replayed from a file exported by our Python (CDIP/OOI records, or JONSWAP synthesis), with a
  start offset per node (independent stretches, as in the Python scenarios).
- For other mobility models: an adapter that finite-differences positions sampled at packet times gives the slow part
  only; the PHY warns once when it falls back to it.

### [C] PHY: `UwDopplerOfdmPhy : public UwOFDMPhy`
- New header `hdr_uwdoppler`: emitting node id, pointer to its Doppler state (simulation shortcut, as `srcPosition`
  already is), emission start (`txtime`), duration, whether and how the transmitter compensated (direction `u_hat`
  used, sensor parameters), the receiver budget implied by the frame format (pilots per symbol or not).
- Transmit side (`endTx`/`startTx`): if the node compensates, choose `u_hat` toward the intended receiver (MAC
  destination → position via [D]; broadcast: a configured reference peer, else no transmit compensation) and record it.
- Receive side (`endRx`, before the PER draw):
  1. emission grid `t in [txtime, txtime + duration]`; `u` from the two positions; `eps(t) = (v_tx(t) - v_rx(t+tau)).u / c`
     plus the slow part;
  2. subtract the transmitter's node stage (if any), the receiver's node stage (if any), then the receiver stage on the
     remainder;
  3. `I_D = interference(residual) + pathFloor`;
  4. `SINR' = Pr (1 - I_D) / (Pn + I + Pr I_D)`, used both in the `MEANPOWER`/`CHUNK` branches and, per carrier, in
     `getOFDMPER` (the Doppler term is the same on all carriers to first order);
  5. log per packet: `I_D`, residual rms, placement, budget (for the paper's network figures).
- `doppler_enabled_ = 0` must reproduce stock `UwOFDMPhy` bit for bit (regression test).
- C3 hook (later): residual Doppler of overlapping users on other subcarriers → leakage term in `uwinterferenceofdm`.

### [D] Registry and cross-layer
- `UwDopplerRegistry` (singleton): node / MAC address → `Position*`, filled from Tcl; used by the transmitter to aim
  `u_hat`. Optional `ClMessage` from MAC to PHY with the next-hop address if `hdr_mac` is not enough.
- Estimate budget at network level: a frame with pilots in every symbol carries less payload. Modelled as a rate
  factor `(1 - pilot_fraction)` on the PHY bit rate, so the budget trade-off appears in throughput, not only in PER.

### [E] Python side (in `Doppler_JSAC/code`)
- `scripts/export_traces.py`: CDIP/OOI/synthetic records → DESERT motion files (`t, pos, vel, acc, lever_vel`).
- `scripts/export_fixtures.py`: per-packet reference cases (trace stretch, sensor and receiver settings, seeds →
  residual series and `I_D`) from the Python harness, for the C++ unit tests.
- `scripts/desert_crosscheck.py`: run the single-link Tcl sample, compare the per-packet `I_D` / SIR distribution
  with `run_link` on the same records.

### Tcl parameters (bind)
Node: `imu_enabled_`, `imu_sigma_` [m/s], `imu_tau_` [s], `imu_latency_` [s], `imu_extrapolate_`,
`lever_corrected_`, `u_error_deg_`, `motion_file_`, `motion_offset_` [s].
Receiver: `rx_stage_` (`none|sym|const2|line2|quad`), `rx_sigma_`, `cp_s_` (prefix length; the FFT length is
`1 / carrierSize`), `pilot_fraction_`, `doppler_enabled_`.
Channel: `floor_powers_`, `floor_grazing_`, `floor_surface_` (or from WOSS in step 6), `sound_speed_`.

## 5. Validation chain

1. Python closed forms ↔ Python waveform simulation (done: 81/85 winners, ±0.7 dB median).
2. C++ model library ↔ Python fixtures (step 1): same numbers per packet.
3. DESERT single link ↔ Python harness (steps 3–4): same SIR distribution on the same records.
4. DESERT network results: only then interpreted.
`doppler_enabled_ = 0` regression keeps the stock behaviour intact at every step.

## 6. Placement in the source tree

- **Recommended: `DESERT_Addons/uwdoppler`** (library [A] + PHY [C] + registry [D]) and
  **`DESERT_Addons/uwwaveposition`** ([B]): no change to core modules, built by the addon mechanism, easy to offer
  upstream later as a pull request to `signetlabdei/DESERT_Underwater`.
- Alternative: core (`DESERT_Framework/DESERT/physical`, `mobility`), cleaner for users but touches `configure.ac`
  and the core build.

## 7. Risks and open questions

- **Velocity of stock mobility models**: no common accessor; the fallback gives the slow part only. Fine for AUV
  cruise, wrong for waves — wave scenarios must use `UwWavePosition`.
- **Live position pointers**: `srcPosition` is evaluated at reception, not at emission; for a 1 km link (0.7 s) and
  slow drift the geometry error is negligible, but the velocities must come from the trace at the right times
  (the provider answers any time, so this is handled).
- **Broadcast and multi-hop**: transmit compensation needs one intended receiver; for broadcast it is aimed at a
  reference peer (gateway) and every other receiver sees its own residual — itself a result worth showing.
- **Time scaling of the packet** (duration × (1 − eps), ~1e-3): ignored at MAC level in v1; noted.
- **Per-subcarrier dependence** of the interference (subcarriers far from the centre see `(fc + f_k) eps`): ±25% of
  `fc` at our band, second order; v1 uses the centre frequency.
- **Upstream changes** to `UwOFDMPhy` (DESERT is active: v4.0.0 is recent) could break the subclass; pin the version.
