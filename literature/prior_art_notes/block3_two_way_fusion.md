# Block 3 prior art: two-way fusion of Doppler measurements for the UWA link

Block 3 (from README_nomab.md and the deck `doppler_link_adaptation_nomab.tex`): node A measures the Doppler scale ε on received ACKs, and node B measures it on received data packets and returns its estimate in the ACK header (≈20 bits). A KF/EKF on a drift-plus-damped-oscillators (swell) model, with a bias state per direction, innovation gating and path-switch handling, fuses both series. This halves the worst sampling gap (2τ+T_a → ≈τ+T_a) and doubles the no-aliasing range for swell Doppler. The fused forecast is then used for the communication link: receiver pre-warping, pilot placement, and a PER threshold rule.

## Q1. Two-way Doppler in time sync and ranging (UWGS, geo-Doppler, D-Sync, DA-Sync, DE-Sync, APE-Sync, TSHL, Mobi-Sync, JSL/TSMU). Does any of them use the fused Doppler for the communication link?

### Takeaway
The closest mechanism is the **DE-Sync / APE-Sync family**, not UWGS. Both ends measure the Doppler scale factor; the beacon **returns its own measurement inside the reply message**; the two are fused (averaged), and APE-Sync then runs a Kalman filter. Measurement and feedback match Block 3 closely, but the purpose (clock skew/offset), the fusion (a plain average per round, with the Kalman state on the clock skew rather than on a Doppler/kinematic model), and the use (none for the communication link) all differ. No sync or ranging paper found uses the fused Doppler for the receiver, frame design or link adaptation. Closeness: **partial** (DE-Sync/APE-Sync, DA-Sync); **tangential** (UWGS, geo-Doppler, D-Sync, Mobi-Sync, TSHL, JSL).

### Cited Findings
- **DE-Sync** — F. Zhou, Q. Wang, D. Nie, G. Qiao, "DE-Sync: A Doppler-Enhanced Time Synchronization for Mobile Underwater Sensor Networks," *Sensors* 18(6):1710, 2018, DOI 10.3390/s18061710 (MDPI, so it is excluded from the local library by owner policy). Two-way Doppler measurement, with the far end's value carried back in the reply: "Upon receiving the synchronization request, beacon A marks its local time as the receiving time-stamp T2 and records the Doppler scale factor … obtained from the physical layer"; the beacon then "transmits a response message back to node B at time T3, which contains T2, T3 and a_BA"; and "when receiving the synchronization response message, node B records its receiving time and the Doppler scale factor". The two directions are fused by averaging: "v_m = 0.5 × (v_AB + v_BA) + ε_v". The fusion is linear regression/LS; there is no Kalman filter in DE-Sync, and the paper is entirely about time sync. — [PMC full text](https://pmc.ncbi.nlm.nih.gov/articles/PMC6021945/)
- **APE-Sync** — F. Zhou et al., "APE-Sync: An Adaptive Power Efficient Time Synchronization for Mobile Underwater Sensor Networks," *IEEE Access* 7, 2019, DOI 10.1109/ACCESS.2019.2912229 (local PDF `pdf/02_doppler_sync_estimation/2019_Zhou_ApeSyncAdaptivePowerEfficientTime.pdf`). It uses the same exchange: beacon N_A "records the Doppler scaling factor a_AB, obtained from the physical layer … the response message also contains T2, T3 and a_BA … when receiving the time synchronization response message, the Doppler scale factor a_AB and the receiving time are recorded by node N_B". Stage 2: "Kalman filter is adopted to track clock skew … only requires a single message interaction". The state is X[n] = [α[n], 1−P]^T, i.e., the **clock skew**. Doppler enters only through "θ[n] = 0.5 × (a_AB[n] + a_BA[n]) + ε, where θ[n] denotes the average of Doppler scaling factor" in the propagation-delay equation. There is no kinematic model, no swell, no use for communication. — [IEEE Access DOI](https://doi.org/10.1109/ACCESS.2019.2912229); local PDF.
- **DA-Sync** — J. Liu, Z. Wang, M. Zuba, Z. Peng, J.-H. Cui, S. Zhou, "DA-Sync: A Doppler-Assisted Time-Synchronization Scheme for Mobile Underwater Sensor Networks," *IEEE TMC* 13(3), 2014 (online 2013), DOI 10.1109/TMC.2013.13. "To refine the relative velocity estimation … the Kalman filter is employed." APE-Sync calls it "the first time synchronization protocol that adopted Kalman filter to track the mobile nodes". It is a Kalman filter on Doppler-derived relative velocity across message exchanges (query (c)), but for sync only, and from the abstract it is not a fusion of both ends. — [library abstract / DOI](https://doi.org/10.1109/TMC.2013.13); [J. Liu PhD thesis, UConn 2013](https://digitalcommons.lib.uconn.edu/dissertations/179) ("employs Kalman filter to reduce the effect of mobility").
- **TSMU / JSL** — J. Liu, Z. Wang, J.-H. Cui, S. Zhou, B. Yang, "A Joint Time Synchronization and Localization Design for Mobile Underwater Sensor Networks," *IEEE TMC* 15(3):530–543, 2016, DOI 10.1109/TMC.2015.2410281 (conference version JSL, SECON 2012, DOI 10.1109/SECON.2012.6275793). The UWGS paper describes it as one that "leverages Doppler effects … incorporates the Kalman filter and a calibration process"; the TMC abstract says it adopts "an advanced tracking algorithm interactive multiple model (IMM) to improve localization accuracy". Its outputs are sync and localization, with no link use. — [MTU repository](https://digitalcommons.mtu.edu/michigantech-p/11065); [UWGS ITU-JFET 2026, §2.6](https://www.itu.int/pub/S-JNL-VOL7.ISSUE1-2026-A03)
- **D-Sync** — F. Lu, D. Mirza, C. Schurgers, WUWNet 2010, DOI 10.1145/1868812.1868815. "A central beacon node broadcasts a request message to unsynchronized nodes, which respond after random delays … By leveraging Doppler shift data, D-Sync effectively addresses the challenges posed by node mobility" (as described in UWGS 2026). It is sync only. — [UWGS ITU-JFET 2026](https://www.itu.int/dms_pub/itu-s/opb/jnl/S-JNL-VOL7.ISSUE1-2026-A03-PDF-E.pdf)
- **UWGS** — M. Ghalkhani, J. Zhang, F. Campagnaro, M. Zorzi, Asilomar 2024, DOI 10.1109/IEEECONF60004.2024.10942777; extended in ITU J-FET 7(1), 2026, DOI 10.52953/xqts2777. It explicitly **avoids** Doppler: "Unlike traditional approaches that estimate radial velocity using Doppler shift, UWGS utilizes multiple one-way pulse signals to establish a geometric relationship between node velocity and range". It is one-way pulses, for time sync, with a packet-loss study. **Correction for the deck:** G3 cites UWGS as "two-way Doppler for time sync". UWGS is actually a geometry-based, Doppler-free, one-way method that criticises two-way Doppler schemes (D-Sync, Mobi-Sync, MU-Sync). The two-way-Doppler sync references should be D-Sync/DE-Sync/APE-Sync/DA-Sync. — [Asilomar PDF](https://signet.dei.unipd.it/wp-content/uploads/2024/12/ASILOMAR_24-2.pdf); local PDF of ITU paper.
- **Geo-Doppler** — J. Liu, J. Chen, J. Zhang, Z. Zou, Y. Ru, W. Guan, "Geo-Doppler Hybrid Mobile Ranging Method for Underwater Acoustic Sensor Networks," OCEANS 2026 Sanya, DOI 10.1109/OCEANS66983.2026.11617170. "Targeting the scenario of a stationary source and a mobile receiver … radial velocity measurements from Doppler factor estimation or node velocity from a DVL … achieves joint velocity-range estimation within a single transmission cycle, avoiding long-delay error accumulation." It is **one-way, single-cycle ranging**, positioned against "traditional two-way ranging methods [that] suffer … due to motion mismatch". There is no inter-packet tracking and no link use. **Correction for the deck:** "two-way Doppler … geo-Doppler ranging" is inaccurate; geo-Doppler is one-way and is framed as an alternative to two-way ranging. — [library abstract](https://doi.org/10.1109/OCEANS66983.2026.11617170)
- **Others (sync only, no link use):** Mobi-Sync (J. Liu et al., IEEE TPDS 24(2), 2013, DOI 10.1109/TPDS.2012.71) uses spatial correlation of velocities; TSHL (Syed & Heidemann, INFOCOM 2006) assumes static nodes; DC-Sync (Sun, Ouyang, Han, IEEE Access 2024, DOI 10.1109/ACCESS.2024.3426357) compensates "variations in radial velocity during message propagation" for "a specific pattern" of motion, still sync only; DAC-Sync (Han et al., ICSPCC 2022, DOI 10.1109/ICSPCC55723.2022.9984584) uses "multiple one-way interactions" for skew and "a two-way interaction" for offset; LT-Sync (Zhang & Wu, JMSE 13(3):528, 2025, MDPI) uses Doppler-derived delay under uniform motion; SMP-Sync / "Time Synchronization with Oceanic Movement Pattern" (Kim, Park, Yoo, KICS 2013, DOI 10.7840/kics.2013.38c.5.486; ICNC 2014, DOI 10.1109/ICCNC.2014.6785447) "controls the instant of transmission by exploiting the feature of an oceanic movement". That last one schedules sync messages by sea movement, which is loosely related to the dropped "send timing to the swell" idea, but it is for sync, with no Doppler fusion. — [UWGS 2026 related work](https://www.itu.int/dms_pub/itu-s/opb/jnl/S-JNL-VOL7.ISSUE1-2026-A03-PDF-E.pdf); [DC-Sync](https://www.researchgate.net/publication/382156868_DC-Sync_A_Doppler-compensation_Time-synchronization_Scheme_for_Complex_Mobile_Underwater_Sensor_Networks)
- **ACB-TS** — S. Bahadar, I. ur Rahman, M. Raza, "Confidence-Driven Adaptive Beacon Control for Time Synchronization in Mobile Underwater Acoustic Communication Networks," Research Square preprint 2026, DOI 10.21203/rs.3.rs-10185388/v1. It adapts the number of sync beacons from "propagation-delay variance, timing-packet loss, and node mobility". Adapting the sampling to mobility is conceptually adjacent, but it targets sync, not Doppler fusion for the link. — [library abstract](https://doi.org/10.21203/rs.3.rs-10185388/v1)

### Inferences
- The "free Doppler measurement on every packet, return the far end's value in the reply, fuse both directions" mechanism has been **published since 2018 (DE-Sync)**, and a Kalman filter was layered on top in 2019 (APE-Sync). The JSAC paper must cite DE-Sync/APE-Sync/DA-Sync as prior art for the *measurement-exchange* mechanism. The novelty claim must then rest on the parts that differ: (i) fusion as an interleaved time series in a kinematic/swell state-space model, rather than averaging within one round; (ii) the per-direction bias and path-switch handling; (iii) the sampling-gap and aliasing analysis; (iv) use of the forecast for the communication chain.
- G3 should be reworded: "Doppler measured at both ends is exchanged and averaged for time sync (DE-Sync 2018, APE-Sync 2019), but never tracked as a kinematic time series nor used for the link." UWGS and geo-Doppler should move to "related one-way/geometric methods" or be dropped from G3.

### Gaps
- The DA-Sync and JSL/TSMU full texts were not read (IEEE paywall). Whether DA-Sync's Kalman state is velocity only or velocity plus acceleration, and whether its Doppler comes from one end or both, is unverified; from the abstract and secondary descriptions it appears one-ended.
- The D-Sync full text was not read (ACM). The description used here comes from UWGS 2026.
- Forward-citation ("cited by") chains of DE-Sync, APE-Sync, DA-Sync, UWGS and geo-Doppler were not checked on Google Scholar. This is the main remaining risk: a 2024–2026 follow-up could reuse the DE-Sync exchange for communication.

## Q2. UWA navigation/tracking with inter-packet Doppler (OWTT + Doppler, LBL/USBL/single beacon, cooperative navigation with range-rate). Is the track ever handed to the modem?

### Takeaway
Many works run a KF/EKF/IMM on Doppler or range-rate taken from communication packets for **navigation**. The closest is Aubry et al. 2019, where an AUV decodes data packets and feeds their Doppler into a Kalman navigation filter. None found feeds the track back to the modem (receiver prior, frame or rate), and none fuses both link directions or models swell. Closeness: **partial** (Aubry 2019), **tangential** (the rest).

The latter uses UWA communication decoding process to estimate both range and relative speed with respect to the reference point in order to improve its navigation via a conventional Kalman filtering." ## Q3. Doppler or channel-state feedback in UWA ARQ/ACK headers; "Doppler feedback" adaptive modulation; UWA ISAC that tracks relative velocity from communication packets and feeds it back.

### Takeaway
No UWA work was found that puts a **Doppler/velocity estimate into an ACK or control header for the communication link**. Feedback in UWA adaptive modulation and coding (AMC) and ARQ carries SNR, CSI or MCS indices. UWA ISAC papers estimate range and velocity, but for sensing, and do not feed them back into link control. Apart from the sync family in Q1, which feeds Doppler back in sync replies, this area appears **empty**.

## Q4. Wave/swell periodic Doppler: aliasing or sampling of oscillatory Doppler by packet exchanges; prediction of swell motion for communications.

### Takeaway
Wave-induced Doppler is well characterised as a channel phenomenon (surface scattering, buoy heave), and one sync scheme times its transmissions to sea movement. No work was found that analyses **aliasing of swell-induced Doppler under packet-exchange sampling**, or that predicts swell motion with a state-space model to drive the link. Closeness: **tangential**.

### Cited Findings
- Walstead & Deane, "Statistics of near surface underwater scattered sound including wave induced Doppler," *JASA* 2016, DOI 10.1121/1.4950090, and "Delay-Doppler characteristics of surface interacting underwater sound," *JASA* 2017, DOI 10.1121/1.5014113. Both characterise the channel, with no prediction for the link. — local library
- Cho et al., "Predicting the Effects of Random Ocean Dynamic Processes on Underwater Acoustic Sensing and Communication," *Sci. Rep.* 10, 2020, DOI 10.1038/s41598-020-61043-w. It predicts channel effects from ocean dynamics but does not track Doppler across packets. — [Nature](https://www.nature.com/articles/s41598-020-61043-w)
- "Analysis of acoustic channels with a time-evolving sinusoidal surface," *Applied Acoustics* 2013: "the delay time and amplitude of single surface bounce paths show periodic time dependence". Channel modelling only. — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0003682X13002545)
- Kim, Park, Yoo, KICS 2013 / SMP-Sync ICNC 2014: "controls the instant of transmission by exploiting the feature of an oceanic movement". This is sea-motion-aware scheduling of sync messages; there is no Doppler aliasing analysis. — [library abstract](https://doi.org/10.7840/kics.2013.38c.5.486)
- DC-Sync (IEEE Access 2024) handles radial velocity that varies during propagation when "the target motion follows a specific pattern". - Local queries `swell Doppler` and `Doppler periodic motion surface buoy` returned only oceanographic or scattering papers (Hayes 2007 *JPO*; Mo et al. 2023 *Chin. Phys. B* on Bragg forward scattering) or nothing. — local library

### Inferences
- The R2 claim (two-way interleaving halves the gap, so the alias-free range for an 8 s swell doubles from ≈2.25 to ≈4.5 km) appears unpublished. No paper found treats swell Doppler as a signal to be sampled by the ACK/data exchange.

### Gaps
- Not searched: radar/sonar and terrestrial or maritime RF literature on two-way Doppler tracking of ship motion (e.g., ship-to-ship links with sea-state prediction), nor wave-motion forecasting for heave compensation in offshore engineering. Those are adjacent fields that might hold the oscillator-model or aliasing analysis outside UWA.

**Bottom line:** nothing found that implements Block 3 in whole. Only one element has strong prior art: exchanging Doppler measured at both ends inside the protocol header and fusing them, which DE-Sync/APE-Sync do for time sync. The open elements are tracking the interleaved two-way series with a swell oscillator model, the per-direction bias and path-switch logic, the sampling and aliasing analysis, and using the fused forecast for the communication link. The searches were not exhaustive: Google Scholar cited-by chains, IEEE Xplore full text and Google Patents were not run.
